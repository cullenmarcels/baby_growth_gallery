# Regression — 回归阶段菜单

## 目标

在 Review 通过后，根据实际影响范围验证本次修改没有破坏既有能力和已归档事实。

## 进入条件

- Review Report 为 `passed`，Plan 状态为 `in_regression`。
- 已从 Execution Log 和依赖关系确定影响范围。

## 必读

1. Plan、Execution Log、Review Report、相关 Tests 和既有 Achievement。
2. Required modules：[`RULESET-SOURCE-EVIDENCE`](../modules/source-and-evidence.md)、[`RULESET-TESTING-QUALITY`](../modules/testing-quality.md)。
3. Conditional modules：UI 回归读 [`RULESET-RESPONSIVE-UI`](../modules/responsive-ui.md)；敏感数据读 [`RULESET-SECURITY-PRIVACY`](../modules/security-and-privacy.md)。

## 强制动作

- 从修改文件、依赖、接口、数据流和历史能力推导回归矩阵。
- 运行项目实际存在且与风险相称的构建、类型、Lint、单元、集成或端到端检查。
- UI 任务覆盖适用的桌面、平板、移动端和状态矩阵。
- 每个未运行项写明原因和风险。
- 不使用 Review 结论替代回归结果。

## 输出证据

- `docs/plans/<PLAN-ID>/regression-report.md`。
- 状态只能是 `pending`、`passed`、`failed` 或 `not_applicable`。
- 报告包含影响范围、选择依据、检查结果、未覆盖项和剩余风险。

## 退出门禁

- `failed` 返回 Development，并在修复后重新 Review 和 Regression。
- `not_applicable` 必须有可核对理由且不得掩盖未验证风险。
- `passed` 或合法 `not_applicable` 且无阻断风险时，Plan 更新为 `acceptance_pending` 并进入 [`Acceptance`](./acceptance.md)。
