# 宝宝首页数据聚合规格

## 目标和现状

将 `/app/home` 从宝宝档案和功能入口页扩展为当前宝宝的成长首页。现有照片、里程碑和成长接口已提供首页需要的摘要，不新增聚合服务、数据库表、迁移或客户端 API 契约。

本规格细化 [SPEC-20260915-8RKJ7RGM](../SPEC-20260915-8RKJ7RGM-baby-growth-mvp/spec.md) 中 Plan H。照片、里程碑与成长数据的既有权限、排序、计算和隐私约束继续适用；不修改其既有规格或归档。

## 首页内容

宝宝档案头部之后按此顺序展示四个独立区块：

1. **最新照片：**最多 3 张已发布照片，使用现有发布照片列表排序；每张缩略图进入对应详情，提供“查看全部”进入 `/app/gallery`。
2. **里程碑进度：**展示现有概览接口的已完成数和总数，提供进入 `/app/milestones` 的入口。
3. **近期提醒：**展示提醒日期在上海当前日（含）至第 30 个日历日（含）之间的未完成里程碑，按提醒日期升序，最多显示 3 条。逾期项和无提醒日期项目不显示；项目链接进入 `/app/milestones/:milestoneId`。
4. **最新成长数据：**分别展示 LENGTH、WEIGHT、HEAD、BMI 最新有效值及测量日期，使用成长概览接口提供的参考结果；百分位仅在参考可用时展示。提供进入 `/app/growth` 的入口。

照片、提醒、成长摘要和进度各自使用现有对应接口与查询缓存。对已有分页查询使用独立首页子键，避免同一缓存键出现不同数据形状/页长；键仍置于现有照片/里程碑资源前缀之下，以复用现有前缀失效行为。成长摘要复用按宝宝生日/性别区分的既有概览键。提醒读取使用当前日期和小页长；响应按日期升序，客户端只保留 30 日窗口内项目并展示最近 3 条。日期使用 `Asia/Shanghai` 日历日。

## 状态、访问与缓存

- 每个区块独立呈现加载、成功、空和失败状态；单区块失败不隐藏其他成功区块，并提供该区块单独重试。
- 空状态只说明该区块暂无内容，并提供现有相关页面入口；不得填充示例或虚构数据。
- 数据查询按 `familyId` 和 `babyId` 隔离；成长查询继续绑定宝宝生日和性别。切换家庭/宝宝时不保留或显示旧上下文的数据。
- 复用已有操作的缓存失效行为。会话失效、当前宝宝归档或服务端拒绝访问时，清除对应受限数据并重新校验 Session 与当前上下文；临时网络错误保留其他可访问区块。
- 所有显示给用户的错误使用中文错误映射。首页只读取服务端按当前 ACTIVE 成员授权返回的数据，不以客户端权限推断代替服务端检查。

## 范围边界

复用现有 API：已发布照片分页列表、里程碑概览、成长概览。无新增公共 API、OpenAPI schema、生成客户端类型、数据库迁移或家庭动态事件。无新图表、变化率计算、医学判断或提醒推送。

页面使用现有导航、设计令牌和无障碍模式，适配 375、834、1440 视口。移动底栏保持当前入口；既有宝宝头像/名称仍可返回首页。

## 验收

- 四个区块各自验证成功、空、加载、失败和重试；照片、里程碑和成长数据入口路由正确。
- 提醒验证上海日期窗口两端均包含、逾期排除、升序、超过 3 项取最近 3 项及空状态。
- 照片按服务端现有顺序最多显示 3 张并正确进入详情；各成长指标取摘要接口各自最新值/日期，参考不可用时不显示百分位。
- 两个合成家庭及不同宝宝切换不串数据；生日/性别更新后成长摘要重取。
- 375、834、1440 下检查布局、键盘可达性、可见焦点、无障碍名称/提示和底栏遮挡。
- 对宝宝、照片、里程碑、成长既有路径执行受影响回归；证据绑定候选提交及 Plan v2 作用域摘要。
