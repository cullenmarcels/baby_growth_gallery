# 照片上传流程与管理中心界面补充设计

## 信息架构

`/app/photos/upload` 是无底栏的专用流程页，顶部只保留返回宝宝首页、当前步骤说明和“我的上传”。桌面使用选择区与可扩展双列处理卡；平板自适应双列/单列；移动端提供“拍照”和“从相册选择”两个等价入口。拖放不是唯一入口，所有文件输入可键盘触发。

`/app/photos/manage` 位于现有 FamilyShell，默认“我的上传”；OWNER/ADMIN 额外出现“家庭已发布”。管理中心只覆盖上传状态、私有草稿、近期发布与回收站，不替代 Plan E 图集、时间轴和详情浏览。

宝宝首页“珍贵照片”卡改为真实上传入口；图集/时间轴导航仍保持“尚未开放”。家庭动态中的 `PHOTO_UPLOADED` 只显示通用“上传了照片”。

## 状态与交互

选择阶段展示格式、20 张和 20 MiB 限制。普通格式用本地 Blob 预览；HEIC/HEIF 用明确处理中占位，收到安全缩略图前不在主线程解码。XHR 展示逐张进度和取消；网络中断保留其他成功项并提供重签/重传。浏览器上传未结束时离开需确认；服务端已处理中的项目允许安全离开。

卡片状态包括待上传、上传中、中断、等待处理、处理中、私有草稿、失败、已发布。草稿可逐张编辑标题、日期、地点和描述，可勾选后原子发布；批量套用只允许日期、地点和描述。草稿明确显示到期日和“编辑不会延长”提示。

丢弃草稿和回收已发布照片均使用带 Escape、焦点圈定与恢复的二次确认；回收站展示永久清理日并可恢复。所有已知 code 映射中文，未知错误不得原样显示服务端或底层库英文。

## 响应式与可访问性

复用现有 CSS Variables、圆角、阴影与 Lucide 图标，不在业务组件硬编码设计色。桌面 `≥1024px`、平板 834、移动 375 同期验收；不得横向溢出，管理中心底栏不得遮挡最后一项。状态、进度、错误和发布结果使用 `aria-live`；字段有 label；焦点可见；确认框支持键盘；尊重 reduced motion。

截图中的云端导入、标签、里程碑关联、长期私密发布、真实姓名/照片/统计均不属于本设计契约。
