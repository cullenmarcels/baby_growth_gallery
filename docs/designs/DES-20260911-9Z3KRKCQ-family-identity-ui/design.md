# 家庭身份、成员权限与动态界面补充设计

## 适用范围与来源

本 Design 补充 `DES-20260908-ZVZKM07B` 未定义的家庭引导、多家庭切换、权限操作、邀请安全状态、异步状态与 834 px 平板布局。视觉方向继续以桌面/移动“家庭空间”截图和既有 CSS Variables 为依据；截图中的人物、口令、照片和成长数据只是版式参考，不是产品数据或可复制资产。

## 应用壳与路由

- `/app` 根据 Session 的 `activeFamilyId` 进入当前家庭；无家庭进入 `/app/onboarding`。
- `/app/onboarding` 同时支持创建家庭和输入邀请口令加入；已有家庭时可从家庭切换器复用。
- `/app/families/:familyId` 展示家庭成员、邀请管理和家庭动态。
- `/app/timeline`、`/app/gallery`、`/app/milestones`、`/app/growth` 使用明确“尚未开放”页面，不展示伪业务数据。
- `>=1024px` 使用桌面顶部 Navbar；`<1024px` 使用紧凑顶部栏和固定 MobileTabBar。375、834、1440 同步验证。
- 移动底栏必须为内容保留安全底部间距，不能遮挡列表、按钮或错误信息。

## 家庭引导与切换

- 无家庭页面先说明“创建家庭”与“使用口令加入”两种真实路径，再由用户明确选择，不自动创建示例家庭。
- 创建表单包含家庭名称和本家庭称呼；加入表单包含邀请口令和本家庭称呼。
- 切换家庭期间保留当前内容并显示忙碌状态；成功后更新 URL、会话摘要和家庭缓存。
- 当前家庭失效时刷新家庭列表：有其他家庭则进入服务端确定的回退家庭，无家庭则进入引导页，并显示可读提示。

## 成员与权限界面

- API 角色分别显示为“创建者”“管理员”“成员”；家庭称呼与角色标签分开。
- 使用称呼首字符和现有渐变生成无照片头像，不新增或伪造头像数据。
- OWNER 可调整 ADMIN/MEMBER 并移除非 OWNER；ADMIN 只能移除 MEMBER；MEMBER 只能查看和退出。
- OWNER 不显示可执行的退出操作，并说明所有权转移尚未开放。
- 角色调整、移除成员和退出家庭均使用键盘可操作的确认对话框；409 时刷新数据并提示状态已变化。

## 邀请界面

- OWNER/ADMIN 创建邀请后，一次性面板显示 `XXXX-XXXX-XXXX`、到期时间、复制按钮和“关闭后无法再次查看”。
- Clipboard API 失败时保留可选择文本并提示手动复制。
- 邀请列表仅显示邀请 ID 对应的创建时间、到期时间和创建者，不显示明文或 digest。
- MEMBER 不请求邀请管理接口，也不显示伪禁用按钮。
- 原桌面截图中的持久明文邀请码被本安全设计明确替代。

## 动态与状态矩阵

- 动态首屏 20 条，使用“加载更多”；切换家庭时 Query key 必须包含 familyId。
- 本阶段只展示家庭创建、成员加入、角色变化、成员退出；墓碑项统一显示“内容已删除”。
- 覆盖正常、空、初始加载、初始失败、分页失败、无更多、权限不足、当前家庭失效、并发冲突、邀请创建/复制/撤销/失效状态。
- 表单和 mutation 防重复提交；错误提供字段提示和顶部摘要，动态消息使用 `aria-live`。
- 对话框支持 Escape、焦点圈定与恢复；所有交互有可见焦点，并尊重 `prefers-reduced-motion`。

## 视觉与隐私边界

- 仅使用 `apps/web/src/styles/tokens.css` 的变量，不在业务组件硬编码设计色值。
- 延续奶油暖阳、白色卡片、柔和圆角和轻阴影；平板采用可伸缩单列/双列组合，不登记额外设备特判。
- 测试、截图和文案只使用合成家庭与成员称呼；不得出现真实儿童照片、姓名、邀请码、手机号或成长数据。
- “个人信息”仍不实现，成人账号与宝宝档案的语义冲突留给后续独立 Design/Spec。
