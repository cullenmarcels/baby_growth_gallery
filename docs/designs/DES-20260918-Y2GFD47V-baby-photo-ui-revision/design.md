# 宝宝档案与照片管理界面修订

适用于当前宝宝档案新建与编辑、照片上传处理卡片，以及“我的上传”管理列表。原图集、时间轴、照片详情和权限设计继续有效；本补充设计不改变照片读取接口与服务端排序。

## 宝宝档案与操作按钮

- 同一操作组的同级按钮等高；编辑表单“取消”和“保存修改”均为现有 44px 主操作高度。图标、筛选与卡片内次级操作保留各自尺寸层级。
- 新建表单出现“取消”，返回 `/app/babies/manage`，包括尚无宝宝时的空档案页。取消不发送创建请求，路由切换后聚焦档案页标题。编辑表单的取消继续只关闭编辑区域。
- 所有操作按钮文案单行展示。新增或更改超过五个字符的文案须先由用户决定；本次只新增“取消”。

## 照片处理与管理

- 处理卡片元数据依次为：标题独占一行；拍摄日期与地点在下一行并列；描述独占一行。375px 时日期与地点纵向排布。
- 上传卡片四边使用相同 16px 内边距，图片与卡片边框之间留白，文字区不再叠加外层 padding。各边间距在无图、处理中、草稿和失败状态保持一致。
- 顶部“我的上传”使用“保存信息”的主操作按钮视觉：44px 高、18px 左右内边距、主题色背景与胶囊边界。返回首页的图标链接仍为独立图标按钮。
- 管理列表使用三列／两列／单列瀑布流。安全缩略图以已有宽高显示自然比例，缺少宽高时回退 4:3；按卡片渲染高度排布，图片加载和分页追加后更新。DOM、键盘顺序保留 API 的更新时间倒序，不用视觉填洞重排内容。
- 图集页面使用同样的三列／两列／单列瀑布流。卡片使用已发布照片的宽高显示自然比例，缺少尺寸时回退 4:3；分页追加和缩略图加载后重新计算卡片行跨度。图集链接和键盘阅读顺序继续保持服务端排序，不使用视觉填洞改变顺序。时间轴保留原有按月份分组的网格布局。

## 状态与验收

375、834、1440 三视口覆盖正常、空、加载、错误、权限变化和预览不可用；无水平溢出。焦点可见，路由退出后的焦点位置明确；瀑布流筛选和加载更多不得丢卡、重卡或让操作按钮被遮挡。
