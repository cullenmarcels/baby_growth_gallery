# 宝宝成长业务闭环界面补充设计

## 适用范围与设计冲突

本 Design 在现有暖色 CSS Variables、桌面顶部导航和 `<1024px` 紧凑顶部栏/底部导航基础上，补充多宝宝、内容页面和完整状态。原移动“个人信息”截图按宝宝档案视觉方向理解，不复用其中示例姓名、头像、生日或关系；桌面成人账号资料继续留在后续独立页面，不把两种语义混合。

## 应用上下文与导航

- 桌面顶部导航增加首页，并在家庭切换器旁提供宝宝切换器；移动端底栏继续是时间轴、图集、里程碑、数据、家庭，点击顶部宝宝头像或名称返回首页。
- `/app` 依次恢复 Session、当前家庭和当前宝宝：无家庭进入家庭引导；有家庭无宝宝时 OWNER/ADMIN 进入创建引导，MEMBER 看到等待管理员状态；有宝宝进入 `/app/home`。
- 切换家庭或宝宝时保留当前内容并显示忙碌状态，成功后再更新路由和查询缓存；失败时保留旧上下文并显示中文错误。

## Plan C 页面

- 宝宝创建表单包含昵称、出生日期、可选性别；头像暂用称呼首字符渐变占位，Plan E 再从真实照片选取。
- OWNER/ADMIN 可从宝宝管理页编辑、归档、查看归档列表和恢复。归档使用键盘可操作的确认对话框，明确“30 天内可恢复，之后永久清除”。
- MEMBER 不显示管理按钮；家庭没有宝宝时显示等待管理员创建的说明，不提供伪可用入口。
- 归档当前宝宝后自动切到服务端选择的其他 ACTIVE 宝宝；没有可用宝宝则进入对应空状态。

## 后续页面方向

- 上传页为无底栏流程页；每张照片独立编辑元数据，批量操作只提供套用能力。处理、部分失败、草稿过期和重复提交必须有明确状态。
- 图集使用真实缩略图网格；时间轴按年月分组；详情页不显示不可用评论或反应。
- 里程碑页展示用户加入的共享清单、已完成记录和应用内提醒，不显示统一医学月龄或逾期判断。
- 成长数据分别展示身高/身长、体重、头围和适用的 BMI/WHO 参考；数值旁固定“仅供家庭记录，不构成医疗诊断”。
- 首页区块允许独立为空，不用示例数据填充统计、照片、提醒或曲线。

## 响应式、状态与可访问性

- 固定验证 375、834、1440；`>=1024px` 桌面顶部 Navbar，`<1024px` 紧凑顶部栏和 MobileTabBar。
- 表单、选择器、确认对话框和分页操作支持键盘、可见焦点、焦点恢复、错误摘要和 `aria-live`；尊重 `prefers-reduced-motion`。
- 每页覆盖正常、空、加载、错误及适用的权限、冲突、过期、处理中状态；移动底栏不能遮挡最后一个内容或错误消息。
- 使用现有 CSS Variables、Lucide 图标、圆角和阴影；业务组件不硬编码设计色值，不使用真实儿童或家庭资料。
